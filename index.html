網頁作業回收模組

讓任何互動網頁教材，多一顆「送出作業」按鈕。後台由我們在產品所屬帳號一次部署；學生按下送出，作答自動歸檔；老師什麼都不用安裝，輸入自己的信箱就能領回自己學生的作業。

一句話說明

這是一套「不用架伺服器」的作業回收架構：由品項端把一小段程式（Google Apps Script）部署在數位產品所屬的 Google 帳號，任何 HTML 教材網頁都能把學生作答送進對應的試算表。學生送出時填「任課老師信箱」，老師之後輸入自己的信箱，就只會看到自己學生的作答。老師端零建置。

已實戰驗證：本模式已在物理科「氣柱共鳴模擬實驗」實際運作，學生端送出與老師端查詢皆通過測試。
學生端體驗
1完成互動教材在模擬實驗、學習單等網頁中作答
2填基本資料班級、座號、姓名、任課老師信箱
3按「送出」作答自動打包送進老師的試算表
老師端體驗
1零設定不用安裝、不用申請、不用部署任何東西
2公告信箱上課時告訴學生「老師信箱欄」填什麼
3查詢下載在查詢頁輸入自己的信箱，看自己學生的作答、下載 CSV
為什麼值得用
特點說明
免伺服器、零費用後台跑在 Google 免費額度內，不需租主機、不需維運
老師零門檻老師不用做任何設定，只要有 email。這是推廣時最大的賣點
嵌入任何網頁學習單、模擬實驗、電子書配套頁，只要是 HTML 都能接，前端只需十幾行程式
收結構化資料不只文字作答：操作紀錄、選項分布、得分等互動資料都能自動打包送出
適用與不適用
適合：互動式數位教材要收「學生做了什麼」的結構化資料，例如模擬實驗的操作數據與論證作答、互動學習單的逐題結果、遊戲化教材的關卡紀錄。
不必用：單純收文字問答或心得，Google 表單就夠了，不需要動用本模組。本模組的價值在「表單做不到的互動資料回收」。

與 Google 表單的差異

Google 表單本模組
學生填答方式離開教材，另開表單手動填寫留在教材內，一鍵自動送出
能收的資料學生手動輸入的內容教材內的任何資料（操作紀錄、得分、作答）
建置門檻零一次性部署約十分鐘（本站附完整教學）
學生端示範：迷你學習單 模擬模式

目前為模擬模式：按送出不會真的連網，資料會出現在下方的「模擬試算表」，讓你體驗完整流程。接上真實後台（技術規格分頁）後，同一顆按鈕就會把資料寫進產品帳號的 Google 試算表。

送出鈕為三態設計（可按、送出中、已送出），避免學生重複送出。

系統架構

前端（任何 HTML 頁）→ POST 送出 → Google Apps Script（產品所屬帳號，一次部署為網路應用程式）→ 寫入產品帳號的 Google 試算表。老師查詢走同一網址的 GET，以「任課老師信箱」為篩選主鍵，各老師只取回自己的資料。無資料庫、無伺服器、無第三方套件。建議每個品項各開一張試算表（各自部署一份），互不干擾。

後台程式碼（GAS 通用範本）

客製只改兩處：HEADERS 欄位定義、doPost 的 appendRow 對應。其餘為驗證過的穩定件，勿動。

const SHEET_NAME = 'Sheet1';
const VERSION = 'v1-〔作業名稱〕';   // 每次改版順手改，方便確認部署版本

// ★客製點 1：欄位（前六欄建議保留，「任課老師信箱」是查詢主鍵）
const HEADERS = ['作業','時間戳記','班級','座號','姓名','任課老師信箱','作答欄位1','作答欄位2'];

function getSheet(){return SpreadsheetApp.getActiveSpreadsheet().getSheetByName(SHEET_NAME)||SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];}
function ensureHeaders(sheet){
  if(sheet.getLastRow()===0){
    sheet.appendRow(HEADERS);
    sheet.getRange(1,1,1,HEADERS.length).setBackground('#1e3a8a').setFontColor('#ffffff').setFontWeight('bold');
    sheet.setFrozenRows(1);
  }
}
/** 學生送出作答 */
function doPost(e){
  try{
    const data=JSON.parse(e.parameter.data);
    const sheet=getSheet(); ensureHeaders(sheet);
    // ★客製點 2：與 HEADERS 一一對應
    sheet.appendRow([
      data.exp||'', data.timestamp||new Date().toLocaleString('zh-TW'),
      data.cls||'', data.seat||'', data.name||'', data.teacherEmail||'',
      data.field1||'', data.field2||''
    ]);
    return json({status:'ok'});
  }catch(err){return json({status:'error',message:err.message});}
}
/** 教師查詢（瀏覽器開 網址?email=xxx，可加 &exp=作業名 篩單份作業） */
function doGet(e){
  const email=e&&e.parameter&&e.parameter.email;
  if(!email) return json({version:VERSION,status:'ready'});
  try{
    const all=getSheet().getDataRange().getValues();
    if(all.length<2) return json({status:'ok',headers:HEADERS,rows:[]});
    const headers=all[0], emailCol=headers.indexOf('任課老師信箱'), expCol=headers.indexOf('作業');
    const expFilter=e.parameter.exp||'';
    const rows=all.slice(1).filter(r=>String(r[emailCol]).trim()===email.trim()
      &&(!expFilter||expCol===-1||String(r[expCol]).trim()===expFilter));
    return json({status:'ok',headers:headers,rows:rows});
  }catch(err){return json({status:'error',message:err.message});}
}
function json(o){return ContentService.createTextOutput(JSON.stringify(o)).setMimeType(ContentService.MimeType.JSON);}
/** 測試用：寫入一筆假資料 */
function testWrite(){
  const sheet=getSheet(); ensureHeaders(sheet);
  sheet.appendRow(['測試',new Date().toLocaleString('zh-TW'),'高二甲','08','王小明','teacher@school.edu.tw','test1','test2']);
}
前端串接程式碼（學生端送出）
鐵則：用 URLSearchParams 包一個 data 欄位裝 JSON 字串（屬「簡單請求」，不觸發 CORS preflight）。絕對不要用 Content-Type: application/json，會被瀏覽器的 preflight 擋死，GAS 收不到（實測踩過）。另外：GAS 冷啟動可能十幾秒到半分鐘、企業網路的安全檢查偶爾會讓「回應讀取」失敗但資料其實已寫入，所以送出鈕要有耐心提示，且失敗時先用 GET 查詢核實一次再判定（實測踩過：畫面顯示失敗、試算表其實有資料）。
const GAS_URL='https://script.google.com/macros/s/★部署網址/exec';

async function submitAnswers(){
  const payload={
    exp:'作業名稱',                                  // 多作業共用後台的區分鍵
    timestamp:new Date().toLocaleString('zh-TW'),
    cls:document.getElementById('cls').value.trim(),
    seat:document.getElementById('seat').value.trim(),
    name:document.getElementById('name').value.trim(),
    teacherEmail:document.getElementById('teacherEmail').value.trim(),
    field1:'...',                                    // 鍵名須與 GAS doPost 的 data.xxx 一致
  };
  const btn=document.getElementById('submitBtn');
  btn.disabled=true; btn.textContent='送出中…';
  try{
    const res=await fetch(GAS_URL,{method:'POST',body:new URLSearchParams({data:JSON.stringify(payload)})});
    const out=await res.json();
    btn.textContent=out.status==='ok'?'✅ 已送出':'❌ 失敗，請再試';
    if(out.status!=='ok')btn.disabled=false;
  }catch(err){btn.textContent='❌ 網路錯誤，請再試';btn.disabled=false;}
}

實作要點：送出鈕三態（可按、送出中、已送出）防連按；必填檢查班級座號姓名與老師信箱；成功後保留畫面作答內容供學生截圖自存。

部署 SOP（品項端做，一次性，約十分鐘；老師不經手）
步驟操作
1用產品所屬的 Google 帳號開 sheets.new 建新試算表並命名（不用建表頭，程式會自動建）
2試算表選單：擴充功能 → Apps Script，開啟編輯器
3清空 程式碼.gs，貼上上方後台程式碼，儲存
4函式下拉選 testWrite 按執行 → 跳授權視窗 → 選帳號 → 「進階」→「前往專案（不安全）」→ 允許。這是自己寫給自己用的程式，此警告屬正常
5回試算表確認出現藍色表頭＋一筆假資料，刪掉假資料
6部署 → 新增部署作業 → 類型選「網路應用程式」
7執行身分選「我」；誰可以存取選「任何人」（必選，否則學生端會被 Google 登入頁擋住）
8按部署，複製網路應用程式網址（…/exec 結尾），填入前端的 GAS_URL
9瀏覽器直接開該網址，看到 {"status":"ready"} 即部署成功
★最常見卡點（重新部署）：改完程式碼按儲存，線上版本不會更新。必須：部署 → 管理部署作業 → 鉛筆圖示 → 版本選「新版本」→ 部署。網址不變，內容才會換新。判斷法：改 VERSION 字串，重新部署後開網址看版本有沒有變。
除錯順序與常見錯誤

前端送出沒反應時，照順序切分問題：① 開部署網址（無參數）沒回 ready ＝部署問題 → 重走 SOP 6 到 9；② GAS 跑 testWrite 後 Sheet 沒資料＝腳本或授權問題 → 重走 SOP 4；③ 瀏覽器 F12 Console 出現 CORS 字樣＝前端用了 JSON header → 改用 URLSearchParams；④ Sheet 有資料但欄位錯位＝appendRow 順序與 HEADERS 不一致；⑤ 畫面顯示失敗但 Sheet 有資料＝回應讀取失敗（冷啟動或企業網路安全檢查），非真失敗 → 前端失敗時先 GET 查詢核實再判定。

症狀原因解法
開網址跳 Google 登入頁存取權沒設「任何人」重新部署，改存取權
送出後 Sheet 沒資料改程式沒重新部署／欄位鍵名對不上發新版本；比對 doPost 鍵名
testWrite 沒反應授權未完成重做 SOP 步驟 4
網址開出來是舊行為用到舊部署網址或沒發新版本管理部署作業確認 VERSION
規劃品項時要預留的設計
項目說明
基本資料欄班級、座號、姓名、任課老師信箱四欄，送出前做必填檢查
送出按鈕三態設計（可按、送出中、已送出）；頁面上加「重新整理會遺失作答」提醒
作答欄位清單規劃時先列出要收哪些欄位（含教材自動打包的互動資料），交給數編對應 HEADERS
後台歸屬統一部署在數位產品所屬的 Google 帳號（老師零建置）；建議一個品項一張試算表
備援繳交建議同時保留「複製文字版」或「下載檔案」按鈕，網路異常時學生仍能交
個資與安全注意
核心觀念：部署時存取權設「任何人」，意思是知道網址的人都能送資料、也能帶信箱參數查詢。因此有三條規矩：

一、不收敏感個資：班級座號姓名即可，不收身分證字號、電話、住址。二、查詢隔離是靠信箱篩選：老師只查得到「學生填了他信箱」的資料；但知道別人信箱的人理論上也能查，若品項在意此點，可在查詢加通關金鑰（if(e.parameter.key!=='金鑰')return json({status:'denied'});），金鑰隨品項發給老師。三、查詢頁連結只提供給老師，不放在學生頁面。

資料集中存放在產品所屬帳號，公司即為資料保管方。規劃時請一併決定：保存期限（例如學期末清空或封存）、誰能開啟總表、以及品項下架時的資料處理方式。
